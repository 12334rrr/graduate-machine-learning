# 单机环境对两个作业的影响评估

> 评估对象：`2026-平时作业及要求.docx` 中的**作业 1**、**作业 2**（截止 2026-11-30）
> 评估前提：全部软硬件只在**当前这台 MacBook Air** 上可用，无实验室服务器、无 NVIDIA 集群、不换机
> 评估日期：2026-10-17　**本文不含任何实现动作**

---

## 0. 结论先行

| 作业 | 影响判定 | 一句话说明 |
| --- | --- | --- |
| **作业 1**（分类/预测 或 论文翻译） | **无影响** | 三个经典模型都是"分钟级"负载，CPU 即可完成，本机算力绰绰有余 |
| **作业 2**（复杂任务 + Transformer） | **有影响，但可控** | 不换机也能做完；影响集中在 **4 处配置差异**（精度、微调方式、算子支持、散热），不影响能否完成，只影响耗时 |
| **真正的风险点** | **不在算力，在可移植性** | "只在这台机器能跑"意味着老师换机审阅时会直接跑不起来，且本机故障 = 数据与代码归零 |

**一句话**：两个作业都**不存在"做不了"**的问题，只存在"怎么配、跑多久、怎么交付"的问题。选题不需要因为硬件而降级。

## 1. 本机体检（实测事实）

| 项目 | 实测结果 | 对作业的含义 |
| --- | --- | --- |
| 机型 | MacBook Air（Mac17,3），Apple M5 | **无风扇被动散热**，长训练会降频 |
| CPU | 10 核（4 性能核 + 6 能效核） | 作业 1 完全够用 |
| GPU | 10 核 Apple GPU，Metal 4，**无 NVIDIA / 无 CUDA** | 只能用 PyTorch **MPS** 后端 |
| 内存 | 24 GB **统一内存**（CPU/GPU 共享） | 训练 86M 级模型够；7B 级不够 |
| 磁盘 | 926 GB，可用 **798 GB** | 数据集（<1 GB）与模型缓存无压力 |
| 系统 | macOS 26.6 | Metal 后端成熟度取决于 torch 版本 |
| Python 工具链 | 无 conda；系统仅有 python3 | 需 venv + 版本锁定，否则换机难复现 |
| 网络 | `huggingface.co` **不可达**（8 s 超时）；`hf-mirror.com` 可用（0.69 s）；ModelScope 可用；PyPI 走阿里云镜像 **4.9 MB/s** | 模型/数据集必须走镜像，否则第一天就卡住 |

**补充实测（PyTorch 2.14.1，4096³ 矩阵乘）**：

| 后端 | 精度 | 实测算力 | 相对 CPU |
| --- | --- | --- | --- |
| CPU | fp32 | 1.87 TFLOPS | 1.0× |
| MPS | fp32 | 3.33 TFLOPS | 1.8× |
| **MPS** | **fp16 / bf16** | **13.6 TFLOPS** | **7.3×** |

**这张表是最有价值的一条结论**：MPS 的 fp32 路径几乎废掉（只比 CPU 快 1.8 倍），但**开 autocast 用 fp16 后快 4 倍**。这意味着"作业 2 在本机能不能跑"的答案，取决于**是否写了 `torch.autocast(device_type="mps", dtype=torch.float16)`**——不是取决于机器本身。

## 2. 作业 1：逐项影响

推荐方案中的作业 1 是 TF-IDF+MLP / TextCNN / BiLSTM+Attention 三模型对比（数据 2–3 万条句子对）。

| 子项 | 影响 | 说明与处置 |
| --- | --- | --- |
| 数据预处理（分词、TF-IDF） | **无** | 纯 CPU，秒级 |
| TF-IDF + MLP | **无** | sklearn，CPU 分钟级 |
| TextCNN | **无** | 小卷积网络，CPU/MPS 均可，10 分钟内 |
| BiLSTM + Attention | **轻微** | MPS 对 RNN 类算子支持不完整，部分 op 会回落到 CPU，甚至直接报错。**处置：BiLSTM 固定用 CPU 训练**，本数据量下 10 分钟级别，不必折腾 MPS |
| 超参搜索（每组 3–5 次重跑） | **无** | 总计 1–2 小时，可接受 |
| 若改走"论文全文翻译" | **无** | 纯写作，零算力依赖——但也不产生工程能力增长（见选题报告） |

**作业 1 结论**：本机硬件对该作业**没有约束**。唯一需要注意的是 BiLSTM 的 MPS 兼容性坑，一行 `device="cpu"` 即可绕开。

## 3. 作业 2：逐项影响

推荐方案中的作业 2 是 DeBERTa-v3-base（86M）+ LoRA 的交叉编码器 RAG 系统。

| 约束点 | 影响程度 | 具体表现 | 处置方案 |
| --- | --- | --- | --- |
| 无 CUDA，只有 MPS | **中** | 多数算子可用，个别算子（如部分 index/scatter、自定义 kernel）会报 "not implemented for MPS" | 优先用 transformers 原生实现；遇到缺失算子用 `PYTORCH_ENABLE_MPS_FALLBACK=1` 回落 CPU |
| **不支持 bitsandbytes 4bit** | **中** | QLoRA 路线作废（该库仅 CUDA） | 放弃 4bit，改用 **LoRA fp16**；86M 模型本就不需要量化 |
| fp32 下算力偏低 | **中** | 若忘记开 autocast，训练慢 4 倍，一个 epoch 从 ~12 分钟变 ~50 分钟 | **强制开 autocast(fp16)**，写进训练脚本默认值；用 bf16 亦可（实测同速） |
| 24 GB 统一内存 | **轻** | bs32/seq256 约占用 8–10 GB，安全；bs64 会紧张 | 用 bs16 + 梯度累积 2，等效 bs32 |
| **Air 无风扇** | **中** | 连续训练 1 小时以上会热降频，速度下滑且不可预测 | 分段训练（每 20–30 分钟存 checkpoint 后暂停）、避免长时间满负荷 |
| HF 直连不可达 | **中** | `from_pretrained` 会卡住直到超时 | 设 `HF_ENDPOINT=https://hf-mirror.com`；或改从 ModelScope 拉权重；**缓存目录改到项目内 `data/hf_cache`**（换机可整体带走） |
| 无 conda | **轻** | 环境不可复制 | venv + `requirements.txt` 锁版本（torch/transformers/peft） |

**耗时估算**（按 2 万训练样本、3 epoch、bs16、seq256、DeBERTa-base 量级，依据上表算力推算，非实测）：

| 配置 | 估算单步 | 单 epoch | 3 epoch 总计 |
| --- | --- | --- | --- |
| MPS + fp16（推荐） | 0.4–0.8 s | 10–17 min | **30–50 min** |
| MPS + fp32（未开 autocast） | 1.6–3.2 s | 40–70 min | 2–3.5 h |
| 纯 CPU | 4–8 s | 100–170 min | 5–8.5 h |

**作业 2 结论**：**能做完，且时间充裕**。前提是把上表 7 项配置一次性写死进代码模板，而不是每次踩坑重来。风险的量级是"多花半天调环境"，不是"做不出来"。

## 4. "只能在这台电脑跑"带来的两个真实风险

这一条比算力重要得多，且用户担心的是对的：

**风险 A：交付不可移植（影响分数）**
老师审阅代码时大概率在 **Windows 或实验室 NVIDIA 机器**上跑。如果代码里写死了 `device="mps"`、绝对路径、Mac 专有依赖，就会在对方机器上直接崩溃——这类"环境问题"在评分时几乎必然扣分。

必须固化的交付规范：
- `device` 自动探测：`cuda → mps → cpu` 三级回退，**不允许硬编码**；
- 精度开关：CUDA 用 fp16/bf16 autocast，MPS 用 fp16 autocast，CPU 用 fp32；
- 全部数据、模型缓存放**项目内相对路径**，不碰 `~/.cache`；
- `requirements.txt` 锁版本 + `README` 写清镜像设置（`HF_ENDPOINT`）；
- 固定随机种子 + 一键脚本（`run_all.sh`），保证"换机一条命令复现"。

**风险 B：单点故障（影响交付本身）**
数据集、模型权重、实验日志只存在这块 926 GB 的盘上。一次重装/进水/盘故障，6 周工作量归零。
处置：代码进 git 私有仓库（含 `requirements.txt`、配置、日志摘要）；数据与权重单独备份到云盘（至少保留一份 `data/` 与 `checkpoints/` 的 tar）；训练日志实时写文件而非只留终端输出。

## 5. 对选题结论的影响

| 判断 | 说明 |
| --- | --- |
| 主选方案是否要改 | **不改**。作业 1 无影响；作业 2 的模型规模（86M）恰好落在本机舒适区 |
| 是否要降级模型 | **不需要**。若时间紧张，可先用 `bge-reranker-base`/`MiniLM-L6`（22M）跑通，再换 DeBERTa-base，速度差 4 倍、指标差 1–3 点 |
| 是否要排除某些候选 | **要**：T9 多模态 VLM（7B 级）在本机是**硬阻断**（内存 24 GB + 无 4bit 量化 + Air 散热），进一步支持不选它；T7 DQN 复现（需千万帧级训练）同样不现实 |
| 进度是否要调整 | **W4（作业 2 训练）由 1.3 周放宽到 1.6 周**，从 0.4 周缓冲中挪 0.3 周；总工期仍落在 11/30 之前 |
