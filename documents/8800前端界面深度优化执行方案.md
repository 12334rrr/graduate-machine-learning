> **对象**：`dataset_hub/`（端口 8800，单文件 SPA `static/index.html` + 标准库后端 `server.py`）
> **目标**：一次性解决当前全部界面体验问题，达到"可直接交付答辩演示"的水准，并固化规范防止同类低级错误复现。

## 0. 硬约束（先读，违反任一条即返工）

1. **改动范围**：以 `dataset_hub/static/index.html` 为主；确有必要时才动 `server.py`（且只做增量，不动路由契约与 SSE 透传逻辑）；**不许改 `hw1_unet/`、`hw2_sam/` 的任何训练/评测代码**，图表重生成一律用独立脚本（见 §9）。
2. **保留不动**：双主题设计系统（CSS 变量）、顶部全局导航、聊天面板、模态/灯箱机制、实时链路（3s `/api/live` + 10s 自动刷新及路由守卫）、术语浮卡、链接检测。
3. **数据纪律**：前端只消费现有 API 字段，**不新增/修改任何指标数字**；表外数字一律不许出现。
4. **备份先行**：改动前把 `static/index.html` 复制到 `.workbuddy/backup/index_<时间戳>.html`；待重生成的 PNG 原图备份到 `.workbuddy/figures_backup/`。
5. **产物位置**：本方案执行中产生的**截图一律放 `.workbuddy/screenshots/ui_opt_v1/`**，不放项目根目录、不放 `documents/`；重生成脚本放 `.workbuddy/scripts/`。交付文档仍放 `documents/`。
6. **环境事实**：`hw1_unet/.conda` 有 matplotlib 3.11.2 + numpy（**无 torch**）；`hw2_sam/.conda` 是空壳；WorkBuddy 托管 venv 无 matplotlib。`hw2_sam/src/plot_figures.py` 经 `common.py` 传递依赖 torch，**不能直接跑**——重生成脚本必须不 import `common`。
7. **中文底线**：界面所有可见文本为中文；专有名词（Dice、IoU、HD95、GPU、SAM、U-Net、ResUNet、Attention U-Net、LoRA、NVLink、ViT、Transformer、ISIC、HAM10000、PH²、SA-1B、CC BY-NC 4.0、Apache-2.0、Open Compute Project）与文件名/路径/URL/代码块保留英文，但**必须在最近处有中文释义**（表头 `title` 属性、术语浮卡或括注）。

## 2. U1 布局重构：左侧章节式导航

### 2.1 问题现状
- `viewHw1`（2136–2450）按"统计卡 4 张 → 实时面板 → Dice 曲线 → 模型对比 → 运行表 → 评测表+数据统计 → 消融+Checkpoints+预测框 → 画廊 → 源码+报告"纵向堆砌，全长约 13 屏；仅靠 2146–2150 的一条横向 sec-nav（统计/曲线/模型对比/运行表/评测/产物）跳转，滚过去就看不见了。
- `viewHw2`（2418–2490）**连 sec-nav 都没有**，9 屏内容纯滚动。
- 术语表（viewGlossary）33 条术语按 7 类分组，同样只能一路往下滚。

### 2.2 影响
演示时想回到"评测档案"或"产物画廊"要滚十几秒；评委看不到整体结构，不知道还有多少内容；hw1/hw2 体验不一致。

### 2.3 具体修改建议
新增**每页左侧章节导航**（组件名 `.page-nav`），数据结构驱动：

```
PAGE_SECTIONS = {
  hw1: [
    {id:"stats",   num:"01", label:"统计总览"},
    {id:"live",    num:"02", label:"实时运行"},
    {id:"curves",  num:"03", label:"学习曲线"},
    {id:"compare", num:"04", label:"模型对比"},
    {id:"runs",    num:"05", label:"运行清单"},
    {id:"evals",   num:"06", label:"评测档案"},
    {id:"artifacts", num:"07", label:"产物画廊"},
    {id:"source",  num:"08", label:"源码与报告"},
  ],
  hw2: [
    {id:"stats", num:"01", label:"统计总览"},
    {id:"live",  num:"02", label:"实时运行"},
    {id:"stages",num:"03", label:"阶段进展"},
    {id:"curves",num:"04", label:"训练曲线"},
    {id:"charts",num:"05", label:"对比图表"},
    {id:"evals", num:"06", label:"评测档案"},
    {id:"artifacts", num:"07", label:"产物画廊"},
    {id:"source",num:"08", label:"源码与报告"},
  ],
  glossary: 按术语分类动态生成（分类键 + "全部"），
  about:    沿用现有各节标题，
}
```

落地要点：
1. **给每个 section 容器加 `id` 与 `data-sec`**（hw1/hw2 各卡片外包 `<section data-sec="...">`），与上表一一对应；这是侧栏跳转与高亮的基础。
2. **渲染结构**：页面主体从"单列 `#app`"改为 `.page-with-nav`（`display:grid; grid-template-columns: 208px minmax(0,1fr); gap:20px`），侧栏 `<aside class="page-nav">` 用 `position:sticky; top:calc(顶栏高+12px); align-self:start; max-height:calc(100vh-顶栏高-24px); overflow:auto`。
3. **hw1 现有 sec-nav（2146–2150）删除**，其功能由侧栏承担；分组筛选 chips（2152–2155）保留在原位（属于"运行清单"section 内部）。
4. **hw2 补章节划分**（stats/live/stages/curves/charts/evals/artifacts/source），与 hw1 编号风格一致。
5. **术语表页**：侧栏列 7 个分类 + 全部，点击滚到对应分组并高亮；架构说明页侧栏列现有各节。
6. **首页/数据集列表/详情页不加侧栏**（长度适中，详情页已有右侧信息卡）。

### 2.4 交互逻辑
- **点击跳转**：`el.scrollIntoView({behavior:"smooth", block:"start"})`，并给 section 一个 `scroll-margin-top: 84px`（避开吸顶导航）；**不得改 `location.hash`**——`route()` 会监听 hashchange 导致整页重渲染、滚动位置与折叠状态丢失。若需分享定位，用 `history.replaceState(null,"", "#/hw1")` 保持路由不变即可，section 状态只存内存。
- **滚动高亮（scroll-spy）**：`IntersectionObserver`（`rootMargin: "-80px 0px -60% 0px"`）观察各 section，可见比例最大者设为 `.active`；章节切换时侧栏自动 `scrollIntoView({block:"nearest"})` 保持可见。
- **首次进入**：渲染完成后聚焦第一个 section，不记忆历史滚动（避免答辩演示时从中间开始）。
- **键盘**：侧栏项为 `<button>`，可 Tab 聚焦、回车触发；`:focus-visible` 有描边。

### 2.5 视觉调整
- 侧栏底色 `var(--card)`、1px `var(--border)` 圆角 12px；每项：编号 `01`（等宽 11px 灰色）+ 中文标签 13px；左侧 3px 圆角指示条，激活时变 `var(--primary)` 且标签加粗。
- 项高 34px、间距 2px；hover 底色 `var(--surface-2)`。
- **移动端 <1024px**：侧栏降级为吸顶横向 chip 条（复用现有 `.sec-nav` 样式，`overflow-x:auto`，置于顶栏下方），grid 改单列——即现有 sec-nav 的移动形态，不新增组件。
- 深色主题下侧栏用现有变量，无需额外配色。

### 2.6 涉及文件
`static/index.html`：CSS 新增 `.page-with-nav/.page-nav/.pn-item`；JS 新增 `PAGE_SECTIONS`、`renderPageNav(view, secs)`、`initScrollSpy()`；改 `viewHw1/viewHw2/viewGlossary/viewAbout` 的结构包裹。

### 2.7 验收标准
- [ ] 桌面 1440px：hw1/hw2/glossary 左侧有常驻章节栏，8 个章节名与页面实际 section 一一对应，无死链。
- [ ] 点击任一章 → 平滑滚动到位、目标不被顶栏遮挡、侧栏高亮随之切换。
- [ ] 手动滚动 → 高亮章节随视野自动切换（不用点击）。
- [ ] 390px 视口：侧栏变横向 chip 条，页面无横向溢出（`document.documentElement.scrollWidth <= innerWidth`）。
- [ ] 7 个路由全部渲染无控制台报错；导航过程不触发整页重渲染（路由 hash 始终是 `#/hw1` 形态）。

## 3. U2 内容折叠：三并列模块 + 长列表

### 3.1 问题现状
hw1 产物区（2424–2433）三张 `col-4` 卡并列：**消融实验**（短表）/ **Checkpoints**（`fileRows` 输出 28 个文件行，最长）/ **预测框导出**（短）。hw2 底部是 Checkpoints（col-6）+ 源码（col-6）。加上两张评测表（hw1 10 行、hw2 24 行）和源码列表，全部平铺，把画廊和报告挤出首屏。

### 3.2 影响
首屏被长文件列表占满；评委看不到"这个实验到底产出了什么图"；页面长度进一步恶化导航负担。

### 3.3 具体修改建议
新增通用折叠组件（不引入框架，原生实现）：

```
.card.collapsible              折叠卡容器（标题行右侧带 ▸/▾ 按钮）
  .ph                          标题行（点击整行也可切换）
    h3 + .collapse-toggle      "展开全部（28）" / "收起"
  .card-body.collapsed         内容区：默认 max-height 0 + overflow hidden + 淡出遮罩
```

折叠规则（写死在渲染层，不靠人工判断）：
1. `fileRows()` 输出的列表行数 > 8 → 该卡默认折叠，折叠态显示前 5 行 + 底部渐变遮罩 + "展开其余 N 项"。
2. 评测表行数 > 8 → 表卡默认折叠（保留表头与"显示全部 N 条"按钮）。
3. **图表卡（含 `.gchart`/`.gbar`/`.gstat` 的任何卡）、统计卡、实时面板、画廊网格本身，一律不加折叠控件**——满足"生成的柱状图直接展示，禁止折叠"。
4. 折叠状态存 `sessionStorage`（键 = 卡标题），同会话内切运行/切路由回来恢复；清空会话即复位。
5. hw1 产物区三卡保持 `col-4` 并列不动，只给中间 Checkpoints 卡加折叠（消融与预测框行数不超阈值，自然不折叠）——这正是"长度差异大的三个并列模块，中间较长内容默认折叠"的落地形态。

### 3.4 交互逻辑
- 点击标题行或 toggle 按钮 → `collapsed` 类切换；高度动画 `transition: max-height .22s ease`（JS 量取内容实际高度做动画，避免固定值裁切）；遮罩淡出。
- toggle 文案随状态切换：折叠时"展开全部（N）"，展开时"收起"；`aria-expanded` 同步。
- 折叠不影响卡内链接/下载按钮可用性（隐藏即可点是 bug：折叠用 `max-height:0 + overflow:hidden + visibility`，不用 `display:none` 残留可聚焦元素——若用 display:none 需同时给内部可交互元素加 `inert` 或 `tabindex="-1"`）。
- 自动刷新重绘（`viewHw1()` 重调用）后按 sessionStorage 恢复折叠态，避免 10s 刷新把用户展开的列表弹回去。

### 3.5 视觉调整
- toggle 按钮 12px、`var(--text2)`，hover 变 `var(--primary)`；chevron 用 CSS 三角或 ▸/▾ 字符，旋转 90° 表展开。
- 折叠态底部 24px 线性渐变（`var(--card)` → 透明）暗示"下面还有"。
- 折叠不改变卡片圆角、边框、间距，网格对齐不变。

### 3.6 涉及文件
`static/index.html`：CSS 新增 `.collapsible/.collapse-toggle/.card-body` 态；`fileRows()` 增加计数返回值或外层包一层；新增 `makeCollapsible(cardEl)` 与 `restoreCollapseStates()`；hw1/hw2 渲染处套用。

### 3.7 验收标准
- [ ] hw1 首屏：Checkpoints 卡默认折叠、可见前 5 行与"展开全部（23）"类按钮；消融卡、预测框卡、所有图表卡无折叠控件。
- [ ] 点击展开/收起动画流畅，无内容跳变；展开态下下载按钮可点。
- [ ] hw1/hw2 评测表默认折叠、可一键展开全部。
- [ ] 开启自动刷新 10s 后，已展开的卡仍保持展开。
- [ ] 柱状图（hw2 提示/延迟/灵敏度三卡、hw1 数据分布/消融/模型对比）始终直接展示。

## 5. U4 图表修复：横坐标标签重叠堆叠

### 5.1 问题现状（三层）
1. **原生柱状图无防重叠**：`gbarSVG`（1532–1620）把全部分类标签水平排在 x 轴，字号 10px、`text-anchor:middle`，无旋转、无抽稀。`hw2LatencyBars`/`hw2SensSpecBars`（2346–2372）分类数 = 评测条数（**24 个**，形如 `e1/gt`、`e3/pert20`），col-4 卡内可用宽度约 370px → 每标签仅约 15px，必然重叠成黑块。

### 5.3 具体修改建议

**（a）`gbarSVG` 标签防重叠算法（新增 `fitBarCats`，必须实现）**

```
输入：cats（分类标签数组）、availW（绘图区宽度 px）、fs（字号）
每个标签宽度估计 w = (CJK字数×1.0 + ASCII字数×0.56) × fs
n = cats.length
  n ≤ 5            → 水平排列（现状）
  6 ≤ n ≤ 10       → 水平放不下（Σw + (n-1)×8 > availW）则旋转 −35°（anchor:end，
                     底部留白 pb = fs×3.4）；放得下则水平
  n > 10           → 直接转横向条形图（分类轴纵向、数值轴横向）：
                     标签永不相交，且 24 条长标签正好适合纵向排列
硬性要求：任何模式下字号 ≥10px，不得为避让缩小字号；宁可转横向、抽稀，不缩字。
```

横向条形图模式规格：条高 = 绘图高/n − 4px，最小 10px；分类标签右对齐排在轴左侧（宽 = 最长标签 + 10px）；数值轴在顶部或底部带单位；`barTip` 复用现有逻辑。hw1 的 3 分类图（data_stats）不受影响。

**（c）robustness.png 重新生成（独立脚本，见 §9 规范）**
