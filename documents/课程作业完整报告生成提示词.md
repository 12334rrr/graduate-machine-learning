### 4.2 作业 1 模型与训练

- U-Net：四次下采样，通道 64→128→256→512→1024，四次上采样，编码器与解码器特征 concat，单通道 logits 输出。
- 默认 `bilinear=True`：上采样为双线性插值加 1×1 卷积，不能写成默认转置卷积。
- ResUNet：块内为残差相加；下采样使用 stride=2 残差卷积；跨编码解码层仍为 concat。它与 U-Net 不只是“加了一条残差连接”，也改变了下采样方式。
- Attention U-Net 的门控生成空间权重图并广播到特征通道；它不是 Transformer 自注意力。`all` 为 g1/g2/g3/g4，`skip` 为浅层 g1/g2，`bottleneck` 为靠近瓶颈的 g4 跳跃连接，并非在瓶颈主干中另加 Transformer。
- 主矩阵为 3 模型 × 3 种子，种子 42、2026、7。默认 batch=8，AdamW，lr=1e-3，weight_decay=1e-4，余弦退火，0.5 BCE + 0.5 Dice。
- `train.py` 默认 30 epoch、patience=8，但正式 `run_all.py` 覆盖为 **12 epoch 上限、patience=6**；实际部分实验提前停止。报告分别列上限、实际轮数、使用的 checkpoint，不能写成全部训练了 12 或 30 轮。
- 分辨率、损失、注意力位置各有一组单种子消融；默认设置复用 `unet_s42` 或 `attn_unet_s42`。不要把六次附加运行误称为全部消融只有六个设置。
- 五折验证将 train+val 合并为 2694 张，划分种子 12345，对 ResUNet 和 Attention U-Net 各跑五折；每个留出折为 539 或 538 张。留出折同时用于 checkpoint 选择和评估，且模型选择与主实验 test 结果有关，须披露，不能包装成完全独立的嵌套交叉验证。

### 5.1 影响实验有效性的实现和权重问题

1. **E2 的翻转与监督未对齐。** 当前 `e2_finetune.py` 的 `run_epoch` 会翻转 `embs` 和 `boxes`，但对应 `gt` 没有同步翻转。检查历史 checkpoint 对应的训练版本及影响范围。即使补齐 GT 翻转，也不能未经验证就宣称“翻转 ViT 特征完全等价于翻转原图后编码”；模型的位置编码等因素需要考虑。旧训练产生的指标不能靠改文字变成修复后的结果。
2. **E3 评测未恢复训练后的提示编码器。** 当前 `evaluate_sam.py::load_stage_weights` 的 E3 分支只加载 LoRA 和 mask decoder，没有加载 checkpoint 中的 `prompt_encoder`；训练脚本却确实优化并保存了它。检查时发现 E3 best checkpoint 的框角点 embedding 与 no-mask embedding 已不同于原版权重，不能用“提示编码器没变”忽略此差异。案例绘图也调用此函数，影响不限于主表。
3. **E3 best 权重与日志峰值不一致。** `e3_lora.csv` 第 3 轮 val Dice 为 0.9114913，但当前 `e3_lora_best.pth` 实际记录第 5 轮，best_dice=0.9025149。训练脚本在更新 best 元数据之前保存 last，跨进程续跑可能使 best 记录回退。核查 best/last/history 和恢复逻辑；同类保存顺序也需检查作业 1 与 E2。不能把日志中的最高分自动当作实际测试权重，也不能假定当前还保存了第 3 轮模型。
4. **当前 JSON 缺少完整的评测版本溯源。** 现有评测主要记录 tag、split、指标，无法仅凭文件名证明其对应哪次代码和哪份 checkpoint。没有版本或哈希证据时，不要把“当前代码推断的流程”写成历史事实已经确证。以后补评须保存代码版本、权重哈希、epoch、完整参数和时间。

### 5.2 必须纠正的统计和比较口径

- **标准差字段有歧义。** `results_summary.json` 的 `models.*.dice_std` 实际由最大值减最小值计算，是极差；真正三种子样本标准差字段为 `dice_sd`。各次 `eval_*.json` 中 `metrics.dice_std` 则是测试样本间的离散程度。不得混用三种量。
- “差异小于标准差”不构成显著性检验。没有预先定义并实际执行适当检验，就写“现有重复实验不足以支持稳定优势”，不要写“统计上不显著”或虚构 p 值。单种子结果没有种子间误差条，1000 张测试图也不等于 1000 次独立训练。
- E2 全量数据与 E3 的前 600 张子集、轮数和增强不同，不是只改变 LoRA 的严格控制变量实验。不能将全部差异归因于 LoRA。
- GT 框、扰动 GT 框和由 GT 生成的点都包含测试标注信息，是模拟交互条件。它们可以作为明确声明的提示条件，但不能宣传为无需标注的全自动测试，也不是性能的数学上界。
- 点提示要按 `points_from_mask` 解释：单点优先前景重心并有回退，多点采用网格区域中心候选及采样。不要写成严格最远点采样、标准 k-means 或真实医生随机点击；名义点数与实际返回点数也应核查。
- “外扩 10%”是四边各按原框宽高的 10% 移动，未截断时宽高约为原来的 1.2 倍，面积并非只增 10%。`perturb_box` 还含约 ±2% 坐标抖动，当前实现对外扩和内缩都会加抖动。`auto10` 的逻辑需单独说明。
- `unet_s42_test_boxes.json` 有 1000 条，其中 6 条空框；评测中空框回退到全图框。`no_prompt_fallback` 不一定计入已在 `build_prompt` 内回退的空框，不能把该字段为零写成无任何回退。
- 空预测的 Dice/IoU 保留在均值中，HD95 则剔除无法定义的样本。必须报告 `empty_pred` 与 `hd95_valid`，防止将“漏检更多、HD95 反而较低”误解为全面更好。例如 BCE 有 33 个空预测，384 分辨率有 80 个空预测。
- HD95 在不同分辨率的像素单位不同。按 `256/size` 缩放只能称为近似尺度换算，掩膜离散化和有效样本也不同；未经统一网格重评，不能称为严格同口径边界对比。
- 当前 E1/E2 评测可读缓存，E3 在线编码。GT 组记录约为 15.01/14.04/2030.20 ms，这些是不同执行路径的历史测量，不是公平的端到端部署速度对比。计时未包含 U-Net 预测框生成，因此也不是整个级联系统时延。
- E3 训练期间参数改变，不能复用原版 SAM 嵌入；但训练完成后，固定模型对同一图像也可以重新缓存嵌入。不要写成 LoRA 模型永久不能缓存，或把约 100 倍差距归因为 LoRA 算法固有开销。
- 训练耗时用实际 `epoch_sec` 汇总，不用分段会重置的 `cum_min` 当总时长。当前 E2 17 轮平均约 120.3 秒、中位数 76.3 秒；E3 6 轮平均约 1484.5 秒、中位数 1412.7 秒。两者训练样本量不同，且存在异常耗时，不能直接宣称缓存带来严格 28 倍加速。
- 不要未经实测写 U-Net 的“10 ms 延迟”、内存峰值或跨数据集泛化。低分不能自动证明“主要原因就是训练轮数少”；没有更长训练和相关对照时，只能提出待验证解释。

## 八 指标 公式与数据处理的统一要求

设二值预测为 P，真实前景为 G，TP、FP、FN、TN 均为像素计数。在两份报告中给出清晰、可渲染的公式及变量定义：

```text
Dice = 2 TP / (2 TP + FP + FN)
IoU = TP / (TP + FP + FN)
Sensitivity = TP / (TP + FN)
Specificity = TN / (TN + FP)
PixelAccuracy = (TP + TN) / (TP + TN + FP + FN)

L_BCE = -(1/N) Σ [y_i log(p_i) + (1-y_i) log(1-p_i)]
L_Dice = 1 - (2 Σ p_i y_i + epsilon) / (Σ p_i + Σ y_i + epsilon)
L = 0.5 L_BCE + 0.5 L_Dice

HD95 = max(Q_0.95({d(a,B): a∈A}), Q_0.95({d(b,A): b∈B}))
```

解释 p 为 sigmoid 概率，实际 BCE 通过 BCEWithLogits 的稳定实现计算；Soft Dice 在每个样本内聚合，再取 batch 均值。A、B 为两掩膜边界，d 是最近边界欧氏距离。当前 HD95 实现是两个方向各取 95% 分位再取最大值，不能换成合并距离后取分位而仍说与源码一致。

聚合与显示必须遵守：

1. 当前 Dice/IoU 等是逐图计算再平均，不是把所有像素合并后的 micro 指标。一个样本上的 Dice/IoU 关系不能直接代入数据集均值换算。
2. 双方为空时 Dice/IoU 约定为 1；仅一方为空时相应重合指标为 0。HD95 对任一方为空不计算，须报告有效样本数。
3. GT 无背景时 Specificity 分母为零，GT 无前景时 Sensitivity 分母为零。原因是 GT 条件而非“预测全前景”；以各实验分辨率下的实际 `spec_valid`、`sens_valid` 计数为准。
4. 三种子样本标准差使用分母 n−1；五折标准差也单独计算；单张评测文件的样本离散程度与它们分开注明。不得对未重复的实验凭空添加误差条。
5. 指标一般保留 4 位小数，HD95/耗时/参数量按需要保留 2 位；计算差值和相对变化时先用未四舍五入的原值。区别“提升 0.03”“提升 3 个百分点”和“相对提升约 x%”。
6. 同表数据必须能追溯到 split、tag、seed、size、prompt、n 和权重；避免把 val 最佳分数写进 test 主表。
7. JSON 中若出现非有限值，解释其定义及有效样本，不把 NaN 当作 0。只读汇总时不要改动原始文件来迎合展示。
8. 当前评测脚本虽在内存中计算逐样本 Dice，保存的 JSON 主要是汇总，不能假定已存有逐样本配对结果。没有样本级或重复运行证据时，不虚构配对检验、置信区间或 bootstrap 结果。
