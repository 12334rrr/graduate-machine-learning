## 2. 架构与数据流核对结论（先说对的）

评估首先确认链路本身设计正确、实现完整，以下均为**实测通过**项，优化时不得破坏：

- **三层架构落地**：数据层（ISIC 2018 原始数据 / SAM 权重 / 嵌入缓存）→ 实验层（hw1 三模型 / hw2 E1-E2-E3 / 级联）→ 展示层（8800 单端口门户），门户对实验产物**只读**，未改动任何实验代码（符合 CLAUDE.md 硬性约束）。
- **实时链路真实有效**：训练/评测进程写 `outputs/progress/*.json` 心跳 → `live_state()` 只返回 10 分钟内心跳 → 前端 3s 轮询 → 实时面板。实测 E3/pert10 评测从 100/1000 推进到 775/1000，面板进度条、百分比、"x 秒前"全部同步更新。
- **指标准确性基线良好**：`data_stats`（train 21.40% / val 26.84% / test 27.98%）与详情页聚合值 23.33%（三 split 加权均值）、882=731+9+142 完全自洽；模型对比 Dice/IoU、HD95（88.1/85.2/83.1）与 `reports/tables.md` 的三种子均值一致；阈值着色（≥0.8 绿 / ≥0.6 橙 / <0.6 红）合理。

- **状态完备性**：loading 骨架 / 空态 / 错误态 + 重试按钮齐全；全路由遍历控制台零报错；NaN 已由 `_sanitize_json` 兜底。
- **性能**：`/api/hw1` 16–49ms/65KB，`/api/hw2` 75–97ms/19KB（嵌入缓存 3694 文件扫描所致），`/api/live` 1.8ms，首页 11ms。完全满足 10s 轮询。
- **安全红线遵守**：密钥仅在服务端 `.env`；页面源码无 `sk-` 明文；全部文件读取有防目录穿越守卫；服务仅绑定 127.0.0.1。

| `/api/live` 文档 | README API 表 / server.py docstring / 架构页均未收录 | ⚠️ 文档缺失 |

### 5.2 指标准细性 —— 基线准确，三处口径错误

- **准确的部分**（不得改坏）：数据统计三 split 与聚合值自洽；模型对比柱状与 tables.md 三种子均值一致；HD95/Sens/Spec/空预测列与评测 JSON 一致；鲁棒性曲线 5 点与 eval 文件一一对应；Dice 阈值着色分级合理。
- **错误 1（P0）**：hw1 stat 面板"测试集 Dice（最佳）0.608 · n=1000 · attn_unet_s42"——均值/单种子/单次 n 三个口径混标（§4.4）。
- **错误 2（P0）**：消融柱状图把"每组仅有的基线配置"包装成维度间对比（§4.4）。
- **错误 3（P0）**：AI 助手因系统提示词过期答错实验状态（§4.8）。
- **隐患**：hw1 全部视图（stat/柱状/曲线）均只展示三种子**均值**，不展示 ±标准差——而 CLAUDE.md 硬性约束"差异 <0.5 点必须用 3 种子均值±标准差或说不显著"。ResUNet(0.6077) vs Attn U-Net(0.6080) 相差 0.0003，无 ±std 时柱状图等高会被误读为"并列第一"。数据现成（evals 里有 dice_std，tables.md 已算好）。

### 5.3 图表可读性 —— 引擎最大短板：非等比缩放

`gchart()` 的 SVG 使用 `preserveAspectRatio="none"` + `style="width:100%;height:<固定px>"`，viewBox 固定 720 宽，导致横向缩放比随容器宽度剧烈变化（实测同一页面 4 张图）：

| 图表 | viewBox | 实际渲染 | 横向缩放 | 后果 |
|---|---|---|---|---|
| Val Dice 曲线（col-8, 1440px） | 720×300 | 873×300 | **1.21× 拉伸** | 文字/圆点/阈值虚线变胖 |
| 学习率 / 每 epoch 耗时（col-4） | 720×132 | 408×132 | **0.57× 压缩** | 文字被挤扁 |
| 损失曲线（col-12, 1440px） | 720×240 | 1339×240 | **1.86× 拉伸** | "0.65"等刻度明显失真 |
| Val Dice 曲线（移动 390px） | 720×300 | 289×300 | **0.40× 压缩** | 轴标签严重挤压 |

`gbar()` 虽用默认等比缩放，但窄容器（col-4≈350px）下 720 宽 viewBox 缩到 0.49 倍、高度仍占 220px，产生约一半垂直空白。此外 14 序列图例换行 3 行、曲线互相重叠（smoke 的 0.258 与主对比 0.6+ 同轴），都对"实时监控可读性"打了折扣。

### 6.1 必须修复项（P0/P1，不修则谈不上"清晰准确描述状态"）

#### P0-1 自动刷新定时器跨视图覆盖页面

- **问题**：`route()` 只停 `livePoll` 不停 `autoRefresh`；开启自动刷新后离开作业视图，10s 后原页面被静默替换为作业视图。
- **影响**：用户在首页/详情页/术语表浏览时页面"自己跳走"且 URL 不变，属于数据可信度事故；定时器永不退出还造成持续无效请求。
- **修改建议**（`dataset_hub/static/index.html`）：
  1. `route()` 开头增加 `stopAutoRefresh()`（与 `stopLivePoll()` 并列）；
  2. `toggleAutoRefresh()` 的定时器回调里增加路由守卫：`if (parseHash().path !== "/" + proj) { stopAutoRefresh(); return; }`；
  3. `autoRefresh` 状态在 `window.addEventListener("beforeunload")` 或 `visibilitychange` 时清理（加分）。
- **预期效果**：任何路由切换 ≤10s 内定时器退出；开启自动刷新后离开作业视图页面稳定不再跳变。
- **验收**：hw2 开自动刷新 → 逐一切换 7 个路由各停留 15s → 页面内容与 URL 始终一致。

#### P0-2 AI 助手系统提示词过期，输出与监控视图矛盾的事实

- **问题**：`SYSTEM_PROMPT` 常量写死"E2/E3 尚未运行、E1 val 5 张 0.757"。
- **影响**：助手对"实验进展"类核心问题给出错误答案，与同页 `#/hw2` 实时数据矛盾，摧毁平台可信度；且每次实验推进都会再次过期。
- **修改建议**（`dataset_hub/server.py`）：
  1. 将 `SYSTEM_PROMPT` 改为**动态生成**：在 `_handle_chat()` 里调用现有 `hw1_state()` / `hw2_state()` 聚合结果，拼装"当前实验状态"段（hw1：运行数/完成数/最佳 Val Dice/最佳测试 Dice±std；hw2：E1/E2/E3 阶段 status + best_eval 的 dice/iou/hd95 + 嵌入缓存 pct + 最近评测文件数），失败时降级为静态文案；
  2. 提示词中删除一切可能过期的具体数字，改为"以服务端注入的实时状态为准，视图没有的数字不编造"；
  3. 聚合失败时明确告诉助手"实时状态暂不可用，建议用户查看 #/hw1 #/hw2 视图"。
- **预期效果**：问"E2/E3 状态"时助手回答与 `#/hw2` 视图一致（E2 0.900 / E3 0.898 已完成）；实验再推进无需改代码。
- **验收**：提问"E2/E3 跑完了吗？各是什么指标？"，回答包含 E2≈0.900、E3≈0.898 且与 `/api/hw2` 一致；停掉服务再问，优雅降级不崩。

#### P0-3 hw1 stat 面板指标口径混标（均值/单种子/n）

- **问题**：`viewHw1()` 的 `bestTest` 是模型级三种子均值，sub 却标注最佳种子 tag 与 `n=1000`。
- **影响**：读者会把 0.608 当成 attn_unet_s42 的单次成绩（实际 0.6226），`n=1000` 也误导（实为 3×1000）；违反项目自身均值±标准差纪律。
- **修改建议**（`dataset_hub/static/index.html` `viewHw1()` L1975-1985、`hw1AggByModel()` L1868）：
  1. stat 标签改为"测试集 Dice（模型均值）"，值显示 `fmt3(dice) + " ± " + fmt2(std)`（std 由该模型下各 eval 的 `metrics.dice_std` 或重新由逐种子值计算），sub 改为"Attention U-Net · 3 种子 × n=1000"；
  2. 同时给"模型对比 · Dice/IoU"柱状图加 ±std 误差线（数据现成），满足"差异<0.5 点须给均值±std"的硬性约束；
  3. 若某模型仅 1 个种子，退化为不显示 ± 并注明"单种子"。
- **预期效果**：0.608±0.015 与 tables.md 完全对齐；ResUNet 与 Attn U-Net 的 0.0003 差异有 std 兜底，不会被误读。
- **验收**：stat 面板数字、sub 文案、柱状图误差线三者与 `reports/tables.md` 第 1 节一致。

#### P0-4 消融基线被包装成"对比"图

- **问题**：`ablation.json` 每组当前仅 1 条基线配置（正式消融未跑），图表并排展示成维度间对比。
- **影响**：视觉形式暗示了不存在的实验结论，属于"不编造指标"红线的边缘违纪；评审者看到会直接质疑数据诚实性。
- **修改建议**（`viewHw1()` 消融面板 L2028-2035）：
  1. 判定逻辑：每组 `<2` 个设置时，不渲染柱状图，改为渲染"基线参考"小表（设置名 + Dice/IoU/HD95）+ 明确空态文案"消融实验尚未运行（`run_all.py --only ablation`），当前仅展示各组基线配置"；
  2. 每组 ≥2 个设置时恢复分组柱状图，并并列展示 Dice/HD95 两个指标（现 `hw1AblationBars()` 死代码可改造复用）；
  3. 删除"各组首项对比"这种隐晦备注。
- **预期效果**：未跑消融时界面诚实显示"待运行 + 基线参考"，不会误导。
- **验收**：当前数据下该面板显示基线表 + 待运行文案，无任何柱状对比图。

#### P1-1 图表引擎非等比缩放失真

- **问题**：`preserveAspectRatio="none"` + 固定高度 + 100% 宽度，横向缩放 0.40×~1.86×。
- **影响**：刻度文字、末值圆点、阈值虚线在所有非 720px 容器上失真；移动端轴标签挤压难读——直接伤害"图表可读性"这一核心目标。
- **修改建议**（`chartSVG()` L1403 与 `gbar()` L1553）：
  1. `gchart` 的 SVG 改为 `preserveAspectRatio="xMidYMid meet"` 删除 `style="width:100%;height:<固定px>"`，改为 `style="width:100%;height:auto;aspect-ratio:<w>/<h>"`，让内容等比缩放；
  2. 或按容器宽度用 `ResizeObserver` 重算 viewBox 宽高后重绘（更彻底，可与主题重渲染合并）；
  3. `gbar` 同步处理窄容器垂直空白问题（高度按宽度比例或设 `max-height`）。
- **预期效果**：任何视口/任何列宽下文字、圆点、虚线均为设计比例；移动端图表可读。
- **验收**：1440px 与 390px 下分别测量 4 类图表的 x/y 缩放比均为 1.00±0.02。

#### P1-2 运行切换后 LR/耗时图与标题不同步

- **修改建议**：`selectHw1Run()` 中同步更新 `#hw1-loss-title`（LR 卡标题）、LR 图容器、每 epoch 耗时图容器（给这两个图加 id 容器，如 `hw1-lr-chart` / `hw1-sec-chart`），或直接改为整页 `viewHw1()` 重渲染并保持滚动位置（与自动刷新同一手法）。
- **预期效果**：切换运行后该行全部图表与标题一致。
- **验收**：切换 3 个不同运行，逐一核对标题与曲线数据归属。

#### P1-3 `total_epochs` 恒空 + `stop_reason` 未展示

- **预期效果**：每个运行显示"已完成 x/12 epoch"与停止原因，支撑报告叙事。
- **验收**：运行表所有行的 epoch 显示带总数；unet_s42 详情显示 early_stop。

#### P1-4 "测试集评测档案"混入 val split 评测
